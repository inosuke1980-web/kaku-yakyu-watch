# 能力表示・スイングの表示契約

起点 main 816dccddd1fe3ab42bcb62d51cb68899113ac481。

## 実データ

選手生成時に talent=47+tier*6+一様揺らぎ（約±21）、各能力に±22を加え、5〜99へ制限する。表示は元値を変更しない固定基準：A 80〜99、B 65〜79、C 50〜64、D 35〜49、E 5〜34。欠測は「—」。tier 0〜4を巡回する固定seedの1000人×7能力では A1061/B1631/C1944/D1497/E867。全能力合算のため、実試合の先発分布を均等に保証するものではない。

打者は contact/power/eye/speed をミート/長打/選球/走力として表示。打順・名前・左右・当日の打席結果の既存欄を再利用する。タイプは順序付き：power>=70かつcontactより8以上高い→強打型、speed>=65かつcontact>=60→俊足巧打型、eye>=65かつcontact・powerよりそれぞれ5以上高い→選球眼型、その他→バランス型。

投手は stuff/control/stamina を球威/制球/スタミナとして表示。stuff>=70かつcontrolより8以上高い→球威型、control>=70かつstuffより8以上高い→制球型、両者>=65→本格派、その他→バランス型。速度能力はないため速球派は使わない。変化球能力とシーズン集計は存在しないため非表示。球種・球速は演出用の既存仕様を維持。

注意：staminaは生成・詳細表示に存在する素の能力だが、現行の疲労判定には使用されていない。eye/control のボール率式は .29+(control-eye)*.0015 であり、名称から期待する効果と逆向き。今回の評価は登録された能力の大小を表し、勝率・四球率の強さを保証しない。試合確率の変更禁止に従い修正しない。

## スイング

既存 resolvePitchCore の見逃し・空振り・ファウル・インプレーの分岐から起動する。乱数追加なし。構えのバット終点を維持するのが見逃し。スイングは直ちにインパクト姿勢へ移り、空振り・ファウルは150ms、インプレーは60msで大きな振り抜きへ移行（既存の75ms後の走者表示へ接続）し、胴体を左右18度回転する。210msに構えへ戻す。空振りは既存whiff反応、ファウルは既存foul反応を維持。見逃し三振は振らない。既存の打球開始時刻・走塁・終了時計は変えない。フレームコールバックは既存animationTokenとdata-swingで中断し、停止後の古いフレームが構えを上書きしない。

## 内野位置の採否

現行基本値：1B[282,149]、2B[257,107]、SS[143,107]、3B[118,149]。本塁[200,293]、二塁[200,47]に対して左右対称。左右打者・一塁走者等によって補正される。

検証候補として2B[265,95]、SS[151,90]のように左右対称を弱め、深さを分ける案は考えられるが、野球上の正解としては未確定。defensiveAlignment→infieldOrigin→groundRangePlan/groundPlayTimesが共有されるため、単純な移動は捕球範囲・時刻を変更する。既存の実関数試験ではSSを横30移動すると捕球時計1314→1308ms、距離52.924→50.010に変化する固定例を確認。描画だけ移動すると元の起点から始まる追球・捕球との接続がずれる。今回は双方とも不採用とし、現行位置を維持する。

安全に実装できるのは、判定座標・移動時計と整合した投影変換を全プレーへ適用する方式、または判定座標変更を別工程で比較する方式。前者も送球・走者・ベースを含む変換が必要で今回の小改修には含めない。候補採用には通常・左右打者・一塁走者・併殺・牽制・盗塁・復帰の連続映像と固定seed全結果比較が必要。
