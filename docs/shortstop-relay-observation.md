# 遊撃手・外野前中継の調査（2026-10）

## 観測と範囲

ユーザーの実観戦で遊撃手の瞬間移動と外野前安打の中継位置の違和感が報告された。具体的なプレー種別は不明。公開ページはブラウザで開いて試合開始・一時停止まで確認したが、対象プレーの連続映像、修正後の公開版は未確認。静止画像から速度等を推定していない。ベスプレPC版の参考方針は従前の引き継ぎを維持する。

盗塁失敗の画面上の `盗塁阻止！` を `アウト` に変更。成功時 `盗塁成功！`、実況ログ、アウト処理、投手記録、その他の走塁アウトは変更しない。ゲーム本体の変更はこの表示文字列のみ。

## 遊撃手

通常位置は [143,107]、守備シフトでは `defensiveAlignment()` で異なる。ゴロの実装 `animateGround()` は打球点へ `moveGroundFielder()` を使って移動し、捕球・送球、判定表示後に同関数で元の位置へ350msで戻す。二塁カバー、盗塁時のカバー、外野中継も同関数を使い、同一token内の複数requestAnimationFrameが同一野手の座標へ書き得る。個々の移動に世代番号はなく、重複時の競合可能性があるが、ユーザー観戦時の原因としては未確認。

`tests/shortstop-relay-study.cjs` の独立VMでは、[143,107]から遊撃ゴロ想定点[158,156]への650msの移動を10ms間隔で測定、最大差1.59 SVG単位、指定点に到達して350msで元の位置へ復帰した。これは本番の `moveGroundFielder` の計測であり、試合全体の捕球・送球時刻を再現した試験ではない。

別の固定条件で、ショートが二塁[200,47]にいるとき `applyDefensiveAlignment(false)` を実行すると、移動補間を使わず通常位置[143,107]へ82.76 SVG単位の直接変更が発生した。実際の `pitch()` は牽制分岐で同関数を呼ぶ。これは瞬間移動しうる処理を再現したものだが、実試合で二塁カバーと牽制がその状態で連続することや、今回ユーザーが見たプレーと同一であることは未確認。牽制前の守備配置を単純にアニメーション化すると牽制開始時刻・既存のカバー競合に影響しうるため、今回の守備ロジック変更は見送る。

## 外野前安打の中継

`animateOutfieldReturn()` は落下点／転がり終点／フェンス跳ね返り点から返球し、外野手がLFならSS、それ以外は2Bを固定点[200,116]へ650msで移動する。返球はそこへ到達する。通常単打はそこで保持、三塁・本塁での勝負または犠飛の場合のみさらに送球を描く。返球の視覚的中継であり、結果を追加で決める処理ではない。

同じ固定テストの方向比較（着地点を便宜上拾球点と仮定、返球時間等はテスト用固定値）：レフト [100,65]→SS [200,116]、センター [200,55]→2B [200,116]、ライト [300,65]→2B [200,116]。650ms時点の野手と、仮想1400ms時点の送球終点が同じ点に到達。実際の落下後の追球・拾球と走者状態の全体再現ではなく、野球としての適正位置を証明するものでもない。

`extraBaseThrowTiming()` も同じ固定点で送球到達を計算し進塁判定に使うため、描画側だけ座標を変更すると走者との時刻・経路が食い違い得る。通常単打の安全な表示改善には、既存判定時刻の維持と中継位置・ボール・野手の一致を同時に確認する設計が必要。今回は修正せず引き継ぐ。
