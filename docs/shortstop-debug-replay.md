# 遊撃手の二塁カバー固定再生（2026-10）

## 開発用固定再生

`?debug=plays` の「遊撃手の二塁カバー・牽制」を再生または最初から再生する。隔離された開発用試合で二塁盗塁成功の演出→SSの復帰→二塁牽制・帰塁→次の投球を見られる。`animateStealPlay()`, `applyDefensiveAlignment(false)`, `animatePickoffReturn()`, `drawPitch()` と既存のフレーム描画を使用。ランナーと球の演出も既存のものを使う。処理順と待ち時間は標準速度の `schedule()` を参考に固定し、ランダムな試合判定や通常の `pitch()` / `trySteal()` 自体は実行しない。したがって本番のランダム分岐・全操作・セーフ判定の完全な再現ではない。

停止・再生し直しは既存の `stop()` と `animationToken` でタイマー・古いフレームを無効化し、選手・球を初期状態に戻す。遊撃手以外の固定再生へ戻す時も走者表示を初期化する。通常URLには機能を表示せず、開発用モードは通常の試合操作を無効にし、試合結果を保存しない。C1・B2mは未採用。本番の試合判定・RNG・速度・守備位置・返球計算・一塁手補間は変更していない。

## 動作競合と通常操作

通常自動進行、二塁走者の盗塁成功後→牽制の固定例は `tests/shortstop-sequence-study.cjs` にて既存関数と仮想時計で再現。400ms [200,47]、約1980ms [143,107]へ復帰、2050msに牽制、3660msに次投球（4倍速のモック）。最大5ms間隔変位2.76 SVG単位。実際のUI操作・実フレームではない。

`pitch()` をカバー中に強制呼出しすると82.76単位の直接座標移動を再現するが、通常スケジュールによる発生は確認していない。一球送りの実装は `stop()`→`pitch()`、stopは古いタイマーを消してtokenを更新する一方、`resetOutfieldPositions()` が直接守備位置へ戻す。pauseもtoken更新と直接リセットを行い、これらの操作自体による表示ジャンプはありうるが、観戦中のユーザーの目撃場面と同じとは未確認。速度変更は `schedule()` の再設定を通るが、全速度・状態の実画面再現は未確認。

同じ `animationToken` のまま同じSSに2回 `moveGroundFielder()` を開始する故障注入では、150msで旧フレームx=177.7、新フレームx=160.3と双方が書き込んだ。移動は互いを失効させない。同一選手への通常操作による重複経路と目撃場面との対応は未確定。全野手への管理方式変更や牽制開始前の待機追加は行わず、通常試合の修正は見送る。
