# ショートの開発用固定再生：Chromium確認（2026-10）

対象はローカルの `index.html?debug=plays`、起点 `764d3e3953e55fe74096fe343f4d2085f965517c`。別の実行環境にあるChromiumを利用してheadlessモード・1280×1000pxで実行した。開発用画面で「遊撃手の二塁カバー・牽制」を選択し、再生・最初から再生・再生の3回を確認した。ボール・走者・ショートの表示を複数の画面フレームで観察し、二塁カバー、守備位置への復帰、二塁への牽制動作、再び戻る動作を確認した。動画ではなく連続スクリーンショットによる観察で、守備動作の完全な自然さや投球・走塁・判定の全ての正しさを証明するものではない。

`tests/shortstop-browser-visual.cjs` は実Chromiumの `requestAnimationFrame` でSSのSVG座標を約6.5秒ずつ記録し、3回の再生・再開始・二塁到達・有限座標・通常フレーム間の過大な飛び・ページエラーを検査する。1回391フレーム、測定された40ms未満のフレーム間最大移動距離は8.86、8.80、8.72 SVG単位。これはフレームごとのSVG属性を実ブラウザで読んだ数値であり、物理的な走力の単位ではない。別実行でも391フレームずつの最大9.69、9.69、9.55。シナリオの初期守備シフトには試合生成によるばらつきがあるので完全固定座標の比較ではない。

この固定再生は既存の盗塁・牽制・投球描画を使うが、通常の試合進行 `pitch()` / `trySteal()` による乱数分岐の実行ではない。今回確認した3回では大きな飛びは確認されなかったが、ユーザーが通常試合で目撃した瞬間移動の原因特定・修正・解消の保証はできない。前工程の強制的な2移動競合・直接座標変更のリスク、通常操作の競合経路は未解決。

公開版への接続は `net::ERR_EMPTY_RESPONSE` で失敗。よってGitHub Pagesの反映状況や公開版での表示は未確認。今回見たものはローカル版であり、iPhone実機・Safari・モバイル表示も未確認。画面画像・大量データ・個人情報・セーブデータはリポジトリに追加しない。実行例： `FIXTURE_CHROMIUM_PATH=/path/to/chromium node tests/shortstop-browser-visual.cjs` （playwrightと対応Chromiumが必要）。外野手捕球、中継位置、ライナーバウンド、投球コースとスイング、二遊間守備位置、H/E、得点演出、死球処理、C1/B2m未採用は引き続き前工程のまま。
