# C1一球契約の隔離検証（2026-10）

## 対象と範囲

`node tests/pitch-contract-isolated.cjs` は既存 `tests/pitch-location-calibration.cjs` の `pitchC` と `nextCount` をVM内に読み込み、C1の球を固定seedで生成する。独立した状態管理器と模擬成績に対する試験で、本番ゲーム、ブラウザ、タイマー、牽制、作戦、走塁、実試合の成績更新を実行していない。球種は試験時の固定入力で、球種抽選の乱数は試験対象外。実際のゲーム接続・採用は行わない。

## 一球データと状態

生成済みデータは再帰的に凍結し、描画と確定に同じオブジェクトを渡す。

- `id`: ゲーム固有のセッション識別子と連番。試験は単一管理器内で1000件の一意性を確認。実装ではゲームIDの重複防止と、同一ゲームで管理器を再生成する際の連番永続化または共有ID発行が必要。
- `context`: gameId、epoch、投手ID、打者ID、イニング、表裏、アウト、ボール、ストライク。epochは塁状態・交代・中断など判定に影響する状況が変わった場合も進める世代番号。実本番に世代番号は存在しないため導入方法の設計が必要。
- `type`、`target{x,y}`、`actual{x,y}`、`zone`、`swing`、`outcome`。zoneは `zone/outside/far`、outcomeは `ball/called/whiff/foul/fair`。位置はC1の抽象座標。
- 状態は管理器の `empty → ready → drawing → committed`。描画中断は `drawing → ready → drawing`、取消は `ready/drawing → cancelled`、文脈不一致は `ready/drawing → invalid`。同じデータで再描画しても再抽選しない。失効条件は文脈・epochの不一致または明示的取消であり、時計による期限は設けない。

生成時にC1の必要乱数を消費する。描画・一時停止・再開・二重確定要求・取消は乱数を消費しない。生成後に取消した場合、消費済み乱数は巻き戻さず、次の球は新しいID・新しい抽選とする。生成前取消では乱数を消費しない。実ゲームで中断を取消とするか再開可能とするかの操作仕様は別途決める。

確定は有効な文脈と未確定状態を検証し、模擬状態の次値を計算してから1回だけ反映する。二重要求は拒否する。投手・打者・イニング・表裏・アウト・カウント・ゲーム・epochの変更は古い一球を失効させる。モックの反映は同期処理であり、既存エンジンの複数関数・例外・途中の副作用を含む原子性を保証したものではない。実接続では再入・例外・部分反映・タイマー競合を検討し、打球結果や得点まで二重実行されない接続器が必要。

## 現行順序と接続方針

通常コードは `pitch()` の牽制判定→守備配置・リード→ `startPitchMotion()` の球種選択・`drawPitch()`→時間経過後の `resolvePitch()` の `tactics()` →実投球数・結果・カウント→打球・走塁・イニング処理→必要時投手交代。スイング演出も `resolvePitch()` の結果分岐中で呼ばれる。作戦成立時には投球数が加算されず投手交代を検討する一方、描画は既に始まっている。現在のpauseはタイマーを消しtokenを更新し、試験モデルの保持・再開とは異なる。

将来の候補は、前球の終了・交代確定→作戦を一度実行→牽制・リードを完了→投手・打者と文脈を確認→球種・一球データを一度生成→描画・スイング→同じデータを一度確定。作戦が成立したらその処理を完了して次の準備へ戻り、牽制時には投球データをまだ作らない。作戦や交代の重複実行を避けるため、前球側の交代と次球側の準備の責務を一箇所に明確化する必要がある。この順序変更は既存乱数・試合テンポ・走者挙動に影響し得るため、今回は設計のみである。

## 描画接続の残課題

`drawPitch(type)` は球種のside/dropから独立した終点を作る。将来は一球のactual位置を受け取り、strike-zone・利き打ちごとの内外・高低・捕手の受球位置を明示した投影を用いる。俯瞰SVGの奥行きと高さは別の概念であり、単純な線形変換を正しいと決めつけない。球種の途中軌道は同じactual終点に収束させる。`animateBatterSwing` と `animateBatterTake` は記録のswing/outcomeを参照し、ストライク・ボールも同じzoneと判断から導く。実画面の視認性・端の球・身体接触・死球の挙動は未設計、未実装。
