# 二塁カバー・牽制の連続計測と中継候補（2026-10）

## 対象と結論

本番ゲームコードは変更していない。前工程の直接座標変更が、通常の自動進行で今回の観戦事象として発生したことはまだ再現できていない。牽制開始前の単純な移動追加はテンポを遅らせ、ショートが二塁牽制をカバーする動きと競合し得る。同一選手の複数の `requestAnimationFrame` は同一 `animationToken` のまま重なりうるため、古いフレームが新しい動作を上書きしない保証もない。根本原因が未特定で安全な終了時刻を証明できないため、本番の描画修正を見送った。観測されたユーザーの現象を否定するものではない。

## 実タイマー処理を使う仮想時間の連続ケース

`node tests/shortstop-sequence-study.cjs` は実コードから `animateStealPlay`, `pitch`, `schedule`, `applyDefensiveAlignment`, `animatePickoffReturn`, `moveGroundFielder` などを読み込み、仮想時計・5ms刻みの模擬フレームで実行する。DOMと投手動作・一部試合状態はモック。二塁への盗塁成功、走者速度55、二塁に走者、4倍速、牽制乱数を固定。公式の `trySteal()` や実ブラウザの描画は実行していない。

|時刻|処理・SS座標|
|---:|---|
|0ms|盗塁カバー開始、[143,107]|
|400ms|二塁カバー到達、[200,47]|
|1150ms|盗塁成功表示、[200,47]（5ms刻み）|
|1680ms付近|300msの通常位置への復帰開始|
|1980ms付近|復帰完了、[143,107]|
|2050ms|牽制開始、[143,107]、直接変更による飛びなし|
|3210ms|帰塁セーフ表示（模擬二塁走者）|
|3660ms|次投球開始のモックが呼ばれる|

牽制時は二塁走者に対しショートがカバーする。帰塁後は牽制動作開始時の位置へ戻る。その他野手のモック初期位置は1B [282,149]、2B [257,107]、3B [118,149]。牽制前の通常守備位置への直接代入は行われるが、上記ではSSは既に通常位置に戻っており差はない。移動は `1-(1-t)^2` の減速型、5ms間隔の最大変位2.76 SVG単位。次投球の実アニメーション、アウト・セーフ判定、同一tokenの全フレームの競合まではこの試験では検証していない。

対照として、上記カバー到達直後の400msに `pitch()` を強制呼び出しすると、[200,47]→[143,107]へ82.76単位の直接変更が生じる。これは自動スケジュール上の事象ではなく故障注入である。通常の一球送りは別途 `stop()` を呼ぶので、この強制ケースをそのまま実際の一球送りの再現と扱ってはいけない。ユーザーの観戦中の正確なプレー・動作順序は引き続き未確認。

## 中継経路の固定比較

`node tests/relay-route-study.cjs` は実 `outfieldPickupTiming`, `throwFlightMs`, `fielderReleaseMs`, `extraBaseThrowTiming` を読み込む。飛行830ms、選手の守備力55・肩55、転送野手65の固定条件。下の仮の落下・拾球点は同一点として扱い、実際の追球や跳ね返りは再現していない。送球開始は1135ms。現行はLF→SS、CF/RF→2B、固定中継点[200,116]。

|方向・拾球点|拾球→中継の距離／時間|中継到着|中継→三塁の距離／時間|一塁走者が三塁を狙う際の送球到着|候補点（例）／候補到着|
|---|---:|---:|---:|---:|---|
|LF [100,65]|112.3／368ms|1503ms|133.9／367ms|2074ms|[135,116]／1987ms|
|CF [200,55]|61.0／326ms|1461ms|133.9／367ms|2032ms|[200,116]／2032ms|
|RF [300,65]|112.3／368ms|1503ms|133.9／367ms|2074ms|[265,116]／2082ms|

走者なしは通常中継点で保持し三塁への2投目をしない。一塁走者ありでも、走者の速度・判断次第で二塁に止まれば通常は保持、三塁を狙って勝負する場合に二投目を表現する。表の到着時刻は一塁走者が三塁を狙う判定用の `extraBaseThrowTiming` の値であり、必ず挑戦する、あるいは必ずアウトになるという意味ではない。

候補は例としてxを拾球位置から本塁方向へ35%寄せ、y=116としただけで、野球上の最適位置や走者の結果を検証したものではない。候補を描画のみで採用すると、現行の進塁判定時刻とのずれがLF -87ms、CF 0ms、RF +8ms生じる。逆に判定側の中継点まで変更すると同じ条件でも進塁の安全率・アウト判定が変わり得て、今回の制約に反する。`animateOutfieldReturn`, `extraBaseThrowTiming`, 本塁への接戦計算（転送時間130msの別経路）、その他の返球計算を共通点・同一時計として整理し、判定を維持する演出設計か、将来明示的に判定変更を認めるかを検討する必要がある。単打では中継から追加送球しないケースを維持する。
