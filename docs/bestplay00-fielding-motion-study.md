## 一塁ゴロと走者

### 既存の事実

`groundBall` は方向・強さ・捕球点・野手能力から `groundRangePlan` と `groundPlayTimes` を使い、範囲外、失策、満塁本塁封殺、打者安打、他内野手による二塁封殺／併殺、通常一塁アウトの順に分岐する。基準1Bは[282,149]、代表打球点[290,182]、一塁[323,169]、二塁[200,47]。一塁手の一塁到着は `pickup+225ms`、一塁へ球を持って移動しsmoothstep `t²(3−2t)` で球と野手を同期。代表固定試験 `first-base-carry` では捕球650ms、踏塁875ms、一塁走者ではなく**打者走者**1100ms、判定表示1210ms。これは固定入力であり全ゴロの実測値ではない。

一塁走者に対する反応は3通りある。元の一塁に残る通常1Bアウトのみ `groundRunnerReaction` を設定し、接触70ms後に[323,169]から[289,135]へ向かい、踏塁時から350msで戻る。進塁する場合は `animateBaseRunners`、二塁封殺／併殺は `animateForceAtSecond` を使う。実データが先に更新されるため描画との対応と、停止・他スプライトとの競合に注意する。第三アウト・回交代など同じ回でない場合は帰塁演出を呼ばない。通常観戦で動かない原因がこの条件外、見えにくさ、競合、配信版の違いのどれかは未確定。

**現在1Bは二塁送球を選ばない。** `couldTurnTwo` は1Bを除外し、1Bでは `relay=null`。他野手の `groundSecondRelayPlan` と `groundForceTimeline` は、二塁への球の到達＋25msと走者の到着を比較し、併殺ではさらに二塁から一塁への到着を打者走者と比較する。二塁送球のカバー野手は既存 `secondBaseCoverPlan` を確認・拡張し、一塁復帰／投手カバーの両立を別に計画する必要がある。1Bが一塁を先に踏んだら一塁走者のフォースは解除される。一塁送球によるアウトと二塁先行封殺の順序を混同しない。

### 次の実装候補（本工程では未実装）

1. まず既存判定を固定した再現専用テストで、無死／一死、一塁残留・二塁進塁・回終了の走者／1B／球／守備結果を同時刻に記録し、ユーザーの目撃条件を探す。通常試合で再現できない場合は未確認とする。
2. 独立したpureな候補計画に「打球接触、捕球点・時刻、送球／踏塁の選択、二塁受球者と到達、走者到着、一塁復帰または投手カバー、二塁→一塁送球、各判定と表示」をまとめる。既存のゴロ・走者関数を使い、失策や範囲外・満塁本塁封殺は既存分岐を維持する。
3. 単純な満塁固定や常時二塁送球にせず、捕球位置、強さ・捕球予定時刻、送球距離、走者と打者の到着、アウト数と受け手の到着を比較する。二塁に間に合わないなら一塁先行、両方間に合うときも必ず併殺にせず、明示した判断条件で選択する。仮の閾値を野球の正解と断定しない。
4. 結果の変更を伴うことを明示し、既存RNGの呼び出し位置・消費数を比較。二塁アウト／二塁セーフ／一塁アウト／併殺／三アウト／走者・得点・個人成績を固定ケースと球場別試合で検証。既存seedとの結果一致を無条件に約束しない。描画だけ二塁送球に変えて内部で一塁アウトのままにしない。

**影響・難易度：中〜高。** 二塁封殺・併殺導入は演出だけではなく、判定・走者・アウト・記録・RNG順序に波及する。今回は禁止されているため変更しない。まず再現・計測を先行し、判定変更が許可された別工程で実装する。

`defensiveAlignment` は `render` の配置と `infieldOrigin` を通じ `groundRangePlan`／`groundPlayTimes` の捕球可能距離・追球時刻にも使用される。単なる見た目の座標変更では安打率・アウト・時刻が変わり得る。投球前 `applyDefensiveAlignment(true)` は距離に応じ250〜650ms、牽制の前は `false` で即配置。盗塁時はSSが400msで二塁カバー後、所定時刻に元の位置へ300msで戻る。二塁牽制もSSがカバーし帰塁後280msで戻る。`shortstop-sequence-study` の固定仮想時計では通常進行でジャンプなし、早期 `pitch()` の故障注入で82.76単位ジャンプ。同一token上の移動競合も試験で確認済みだが、ユーザー目撃と同一原因とは未確定。

候補：まず固定位置表示・場面別座標と実画面を並べ、二塁・投手・内野の見た目とユーザーの違和感を照合する。表示だけの候補座標と現在の判定原点の差は必ず記録し、球・グラブ・捕球時刻が不一致なら採用しない。表示／判定の原点を同時に変える場合は別工程として8球場×1000試合と能力別・打球別の差を測定する。**難易度：計測は小、位置変更は中〜高。**

## 外野中継と返球

現行 `outfieldRelayDecision` は通常単打で二塁方向の中継点に返して保持し、三塁／本塁で実際の接戦がある時だけ当該塁へ次投する。単純な「二塁へ返球」とは別で、保持の場合は二塁への追加送球やアウト判定はない。`animateOutfieldReturn` はLF→SS、CF/RF→2Bを使用し、受け手は650msで候補点へ向かう。`release`から球が中継へ、`atRelay`で受球、`atRelay+relayPause`で二投目、`atGoal`で到達、既存期限内で復帰する。

現行の単打描画点は `pickup + 0.52*(goal−pickup)`。時間計算は依然旧固定[200,116]を使い、変更後の経路に古い時間予算を割り当てる。以下は固定ライナー850ms・肩／守備55のテストの値で、各点の野球上の正解は未検証。

|方向／拾球点|中継|二塁方向で保持|三塁勝負|本塁勝負|返球開始→中継受球|
|---|---|---|---|---|---|
|左翼 [90,15]|SS|[147.20,31.64]|[83.24,95.08]|[147.20,159.56]|1230→1628ms|
|中堅 [200,-25]|2B|[200,12.44]|[136.04,75.88]|[200,140.36]|1230→1621ms|
|右翼 [310,15]|2B|[252.80,31.64]|[188.84,95.08]|[252.80,159.56]|1230→1628ms|

左翼／右翼の三塁到着2199ms、本塁2234ms、中堅の三塁2192ms、本塁2227ms。野手の元位置→候補点を650msで移動できると固定するため、遠い点で実際の移動速度が不自然になり得る。CFでも打球寄りや送球先によりSS側が自然な場合があり、既存CF→2B固定では役割の競合・守備上の状況を表しきれない。これは座標と役割からの**懸念**であり、個別の目撃映像における原因の確定ではない。

設計候補は(1)走者と勝負先を決定、(2)その塁の受け手・カバーと競合しない中継候補を選ぶ、(3)球の直線上に置くことに加え内野／外野境界、現在守備位置からの到達可能距離と身体の向きを考慮、(4)中継受球前の到達、二投目開始、次塁到達、帰還を同一計画で作る。ライン上の比率は上限・候補の一つで、52%を普遍値にしない。内野・外野境界の形は球場ごとに異なり、単一の固定yを正解にしない。

**判定上の注意：** `extraBaseThrowTiming` と `hit` の本塁競争は旧[200,116]基準。可視点だけを動かす案は結果・既存時間を維持できるが、距離と見た目の送球速度が矛盾し得る。新しい経路を判定側にも採用すれば到着時刻・アウト率・進塁・得点が変わり得るため、別工程で比較・承認が必要。本塁競争の転送130msと描画の `fielderReleaseMs(65,65,true)` 204msの差も未解決。**難易度：方向別の可視計測は小、統一計画と判定の再校正は高。**

## 得点演出の中断・サヨナラ

`addRuns` が内部得点を確定し `visualScoring` に走者を登録、通常はホーム最終描画フレームの `scoreRunnerArrived` で補助表示を１点ずつ更新する。スコアボード自体は先に更新され得る。サヨナラでは `addRuns`→`finish`→`stop` が先に走りtokenを変え、ホーム到達の描画が実行されない。停止・一球送りでもtokenが無効化され、残りの走者描画を復元しないため補助表示が欠け得る。

最小案：結果・保存の確定と表示の完了を分離した**試合単位の一時的な演出状態**を設計し、サヨナラ時には新規投球を防ぎつつ既存の走者到達と表示を完了してから通常の描画終了処理へ移る。停止・再開は再描画可能な進捗と重複防止IDが必要で、既存 `stop()` の全副作用（タイマー、token、保存、試合終了、次試合）を分解して固定テストする。演出を長くするだけの待機や、内部結果の巻き戻しはしない。歩行・本塁打・複数得点・クロスプレー・試合中断／新試合・タブ非表示もテスト対象。全アニメーションの共通時計化が必要なら停止し、影響範囲を別途設計する。**難易度：中〜高、未実装。**

## 優先順と完了基準

1. **次回の最小工程：一塁ゴロの再現・計測。** 通常の `resolvePitchCore`→`groundBall`→`render`→各走者描画を通す固定入力で無死／一死、一塁残留・進塁、他野手の二塁封殺／併殺を連続フレーム観察。開始・踏塁・二塁到達・各判定・旧フレームと実際の球／走者／野手を同座標・同時計で記録。中断と次球を含め、ユーザーの現象を再現できた場合のみ描画の限定修正を検討。1Bからの二塁送球は、次の段階で判定変更を明示的に許可された後に進める。
2. 中継は3方向×保持・三塁・本塁を現行時計のまま画面・数値比較し、候補の到達可能性と見た目を検証。位置変更は時計・判定の影響を切り分けた後。
3. 二遊間は場面と打者左右を揃えた視覚比較と、同一打球の捕球確率・所要時間の感度分析。候補は実画面と検証で選び、結果変更を勝手に反映しない。
4. 得点中断／サヨナラは別の固定ケースから。公開版・iPhone Safari実機、通常試合の連続プレーはそれぞれ実際に確認した範囲だけ報告。
